What you get

Seven capabilities, one contract, no market data.

Built on data.sec.gov and www.sec.gov only. No quotes, no estimates, no news, no vendor feeds, so nothing you redistribute carries someone else's licence.

GET /v1/companies/search

Company lookup

Ticker, CIK or name. CIKs normalize to 10 digits; tickers are case-insensitive; name matches are ranked and labelled, never claimed as definitive.

GET /v1/companies/{cik}/filings

Recent filings

Form type, filing date, SEC acceptance timestamp when the source has one, accession number and the filing index URL. Newest first, stable tie-break.

GET /v1/companies/{cik}/facts

Normalized facts

Revenue, operating income, net income, total assets, operating cash flow. Units, periods, source tag, mapping version and quality status on every row.

GET /v1/companies/{cik}/freshness

Freshness you can measure

Last successful fetch, first-detected and processed times, and latency only where two comparable timestamps exist. No invented SLA.

POST /v1/watches

Filing notifications

Webhooks signed with HMAC-SHA256, at-least-once with stable event IDs, retries with backoff, delivery status you can query.

GET /v1/exports/facts

Bounded exports

CSV or JSON with every provenance column, capped per request and metered by rows and bytes. Full-universe dumps are refused by design.

Pipeline

From SEC payload to cited fact in six steps.

01 fetchConditional requests to the SEC with a descriptive User-Agent, rate limiting and backoff.
02 identifyCIK becomes the canonical ID. Tickers are attributes, not identity.
03 upsertFilings keyed by CIK + accession. Re-ingestion changes nothing; first-detected time is kept.
04 normalizeXBRL tags map to five metrics through a versioned, deterministic precedence list.
05 classifyPeriod class comes from the actual duration. A 9-month year-to-date value is never called a quarter.
06 notifyNew accession numbers fan out to active watches as signed, deduplicated events.

AI friendly

Designed to be called by a model, not just read by a person.

Tool-calling works when the schema is strict, errors are predictable and every answer carries evidence. The API is shaped around those three things.

Machine-readable surface

OpenAPI 3.1 at /openapi.json with security schemes and every response code. A plain-text llms.txt summarises endpoints, limits and limitations for context windows. Stable error envelope: {"error": {"code", "message", "request_id"}}.

Evidence on every row

Each fact carries source_url, source_tag, accession_number, mapping_version and quality_status, so an agent can cite the filing and flag ambiguous_mapping or derived values instead of presenting them as reported.

Honest nulls

Missing data stays null. Timestamps the SEC does not publish are null. Values that fail to parse are invalid_source_value. A model that reads this API never has to guess whether zero means zero.

FAQ

Straight answers.

Is this real-time market data?

No. There are no prices, quotes or trading signals anywhere in the product. The API covers SEC filings and the structured facts the SEC publishes about them.

How fresh is "fresh"?

Watched companies are polled every five minutes by default. The freshness endpoint reports the last successful fetch, when a filing was first detected and when it was processed, and it only computes a latency figure when the SEC provides a precise acceptance timestamp to compare against.

Which metrics and companies are covered?

Five canonical metrics from standard us-gaap tags exposed by the SEC company-facts API, for companies that have been ingested. Coverage grows on demand: looking up a CIK triggers ingestion. IFRS filers and custom extension tags are not covered yet, and a missing value means the SEC endpoint did not expose it.

Can I redistribute the data?

Everything comes from SEC-hosted sources and each row links to its filing. Before building a bulk redistribution product on top, read our data-rights page and get your own legal review; we document the open questions rather than pretend they are settled.

How do webhooks stay trustworthy?

Each watch gets its own secret. Deliveries carry a timestamp and an HMAC-SHA256 signature over the body, a stable event ID for deduplication, and we never follow redirects or deliver to private network addresses.
