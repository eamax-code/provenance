Quickstart

  1. Make a call, no sign-up

    This asks for Apple's annual revenue with the public demo key. Pick how you work; each tab runs as pasted.

    curl -s "{{BASE}}/v1/companies/320193/facts?metric=revenue&period=annual&limit=3" \
  -H "X-API-Key: demo"
    pip install "provenance-client @ git+https://github.com/eamax-code/provenance#subdirectory=clients/python"

from provenance_client import Client

client = Client(api_key="demo", base_url="{{BASE}}")
for fact in client.facts("320193", metric="revenue", period="annual")[:3]:
    print(fact["period_end"], fact["value"], fact["source_url"])
    const res = await fetch(
  "{{BASE}}/v1/companies/320193/facts?metric=revenue&period=annual&limit=3",
  { headers: { "X-API-Key": "demo" } },
);
if (!res.ok) throw new Error((await res.json()).error.message);
const { data } = await res.json();
data.forEach((f) => console.log(f.period_end, f.value, f.source_url));
    claude mcp add --transport http provenance \
  {{BASE}}/mcp \
  --header "X-API-Key: $PROVENANCE_API_KEY"

    With no key set, the demo limits apply. Then ask: "What was Apple's revenue in each of the last three years, and which filings report it?"

    Run it here, in the playground, without leaving the browser.

  2. Read the citation

    Each row has a source_url to the filing on sec.gov and its accession_number. Link the figure to that page wherever you display it. The next section explains the rest of the row.

  3. Swap in your own key

    The demo key covers the showcase companies, ten rows a page and 20 requests a minute. For every company, exports and alerts, create a free account and make a key in a minute. It is shown to you once; keep it in an environment variable, not in code:

    export PROVENANCE_API_KEY="your key"
curl -s "{{BASE}}/v1/companies/789019/facts?metric=revenue&period=annual&limit=3" \
  -H "X-API-Key: $PROVENANCE_API_KEY"

  "metric": "revenue",
  "value": 416161000000,
  "unit": "USD",
  "period_start": "2024-09-29",
  "period_end": "2025-09-27",
  "period_class": "annual",
  "fiscal_year": 2025,
  "form_type": "10-K",
  "filed_date": "2025-10-31",
  "accession_number": "0000320193-25-000079",
  "source_tag": "RevenueFromContractWithCustomerExcludingAssessedTax",
  "source_url": "https://www.sec.gov/Archives/edgar/data/320193/000032019325000079/0000320193-25-000079-index.html",
  "mapping_version": "1.1.0",
  "quality_status": "ok",
  "derived": false
}
  • source_url and accession_number identify the filing. source_tag is the XBRL concept the company used; mapping_version is the rule set that mapped it to revenue.
  • quality_status is ok, partial, ambiguous_mapping, invalid_source_value, suspicious_period (a period ending before 1993 or two or more years after its filing: almost always a typo in the filing; never the latest figure) or derived. Show anything other than ok with a note.
  • derived: true means the value was computed, for example a fourth quarter as the year minus nine months. Say so when you show it.
  • period_class comes from the period's dates, not the company's label, so a year-to-date value is never mistaken for a quarter.
  • A value the SEC data does not contain is null, never 0.

Point in time with as_of

Backtests need what was known on a date, not what is known now. Add as_of=YYYY-MM-DD to facts, the screen or search and you get only observations filed by that date. A restatement filed later is invisible.

# revenue as it stood on 15 January 2024
curl -s "{{BASE}}/v1/companies/320193/facts?metric=revenue&as_of=2024-01-15" -H "X-API-Key: $PROVENANCE_API_KEY"

# the largest companies by total assets, as known on 31 March 2025
curl -s "{{BASE}}/v1/facts/screen?metric=total_assets&year=2024&as_of=2025-03-31" -H "X-API-Key: $PROVENANCE_API_KEY"

To see every observation of a period, including restatements and alternative tags, add include_all_observations=true.

Why it matters: on the data loaded on 15 November 2026, a 2023 revenue screen has 4,895 companies, but only 3,563 had filed by 31 March 2024, and 288 have restated since. A backtest on today's data would have traded on 1,332 figures nobody had yet. examples/point_in_time.py runs this comparison for any metric and date.

Company overview

GET /v1/companies/{cik}/overview returns a company in one call: its identity (display name, LEI and how it was matched, state of incorporation and the filing it comes from, auditor), key figures with the change on the year before, ten years of annual figures, recent events, 13F ownership, segments, insider activity and leadership. It is the payload the Explorer's Overview tab draws. Every value carries its filing link, accession number, XBRL tag, mapping version and quality status, so you need no second call to cite it.

Key figures add ttm, the trailing twelve months: for income-statement and cash-flow metrics the sum of the last four quarters, for balance-sheet metrics the latest quarter-end value. It is marked derived and lists each quarter it uses. It is given only when all four quarters exist, follow on from each other, end within the last 15 months and share one unit; otherwise it is null. as_of builds the overview from the filings made by a date.

curl -s "{{BASE}}/v1/companies/320193/overview" -H "X-API-Key: $PROVENANCE_API_KEY"

Financial statements

GET /v1/companies/{cik}/statements/{statement} returns a whole statement in one request: income, balance or cash_flow, every row, up to 20 years (period=annual, 12 by default) or 80 quarters (period=quarterly, 40 by default), oldest first. Each cell is the value /facts returns for that metric and period, with its filing, tag and quality status. A missing value is null, never 0.

Derived rows follow the reported ones: gross, operating and net margin (in %), current ratio and debt to equity (x) and free cash flow. Quarters worked out as the year less nine months are marked too. Each is derived: true with its formula and inputs; send include_derived=false to leave them out. Nothing is converted: values stay in the company's reporting currency.

curl -s "{{BASE}}/v1/companies/320193/statements/income?period=annual&periods=12" -H "X-API-Key: $PROVENANCE_API_KEY"

Company timeline

GET /v1/companies/{cik}/timeline puts a company's history in one list, newest first: filings, 8-K items with an event type (results, auditor change, restatement and the like), officer changes from 8-K item 5.02, auditor changes, going-public steps and lock-up ends, insider buying and selling signals from Form 4, and each quarter's 13F holder count. Each item has a plain title and links its filing.

curl -s "{{BASE}}/v1/companies/320193/timeline?types=8k_item,officer_change&limit=50" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/companies/320193/timeline?cursor=NEXT_CURSOR" -H "X-API-Key: $PROVENANCE_API_KEY"

Watchlists

A watchlist is a named list of companies with the columns you choose, stored with your key. Read it back as one row per company, follow the timeline of every company in it, or turn it into watches in one call. Another key's list returns 404. Revoking a key deletes its lists.

Calendar

GET /v1/companies/{cik}/calendar, GET /v1/watchlists/{id}/calendar and GET /v1/calendar?ciks= (up to 50) list dated items: 10-K and 10-Q due dates, late filing notices (NT 10-K, NT 10-Q), IPO lock-up and quiet-period ends, and Form 144 windows. Due dates, lock-up and quiet-period ends are derived from rules and the company’s own filings: each says derived: true and gives its basis. Companies going public

Provenance reads every new EDGAR filing each hour. Companies that register to go public are added on their first filing, and /v1/ipos shows how far each one has got: confidential draft (DRS), filed (S-1, F-1, or Form 10 for a spin-off), amended, effective, listing (8-A and the exchange's certification), priced (424B4) or withdrawn. Each step links its filing.

# priced in the last 30 days
curl -s "{{BASE}}/v1/ipos?days=30&stage=priced" -H "X-API-Key: $PROVENANCE_API_KEY"

# everything moving this quarter, spin-offs only
curl -s "{{BASE}}/v1/ipos?since=2026-10-01&kind=spin_off" -H "X-API-Key: $PROVENANCE_API_KEY"

Only first-time registrants are listed: a company that filed annual or quarterly reports before registering is raising money, not going public. Priced means the final prospectus is filed, not that trading has started; the ticker appears once the SEC lists one. New filings of these companies reach the event feed and your watches like any other.

Insiders, holders and subsidiaries

One call returns a company's connections as nodes and edges: its directors, officers and 10% owners (Forms 3, 4 and 5), the other companies those people report on, its holders above 5% (Schedules 13D and 13G) and its subsidiaries (10-K exhibit 21). Every edge carries the filing it comes from, and as_of rebuilds the picture from the filings made by a date.

# the whole graph, or some layers: insiders, interlocks, holders, subsidiaries
curl -s "{{BASE}}/v1/companies/320193/graph?include=insiders,holders" -H "X-API-Key: $PROVENANCE_API_KEY"

# the same data as lists
curl -s "{{BASE}}/v1/companies/320193/insiders" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/companies/320193/insider-transactions?code=P,S&since=2026-01-01" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/companies/320193/subsidiaries" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/companies/320193/holders" -H "X-API-Key: $PROVENANCE_API_KEY"

Subsidiaries come with the names that are new or gone since the previous year's exhibit. With your own key, a company's exhibit 21, 13D/G filings and newest Forms 4 are read from EDGAR when they are more than a week old; the response says refreshing: true while that runs. The demo key reads what is stored. The Explorer draws the graph in its Connections tab.

Ownership from 13F

Institutional managers report their holdings on Form 13F-HR up to 45 days after each quarter ends. /v1/companies/{cik}/ownership returns the latest complete quarter: the managers holding the company, ordered by value, each with its change since the quarter before (new, added, reduced, exited) and the 13F filing it comes from, plus the holder count and the share of stock outstanding held by these managers.

That share is derived: 13F shares held divided by the shares outstanding on the company's cover page, both listed as inputs. For companies with several share classes it is left out, because shares are not added across classes. An amended 13F that restates a quarter replaces the original. as_of shows ownership as it was known on a date.

# the largest holders of Apple at the latest complete quarter
curl -s "{{BASE}}/v1/companies/320193/ownership?limit=10" -H "X-API-Key: $PROVENANCE_API_KEY"

# as it was known on 1 August 2026
curl -s "{{BASE}}/v1/companies/320193/ownership?as_of=2026-08-01" -H "X-API-Key: $PROVENANCE_API_KEY"

# or ask your agent (MCP tool institutional_ownership):
# "Who are Apple's largest institutional holders, and who added or exited last quarter?"

Segments

/v1/companies/{cik}/segments returns the business, geographic and product breakdowns from the latest annual report: revenue and, where reported, operating or pretax income for up to three years, each segment's share of revenue, the reconciling items the filing tags, and the consolidated total. When segments do not add up to the total within 1% and no reconciling item is tagged, the year is marked unreconciled. Labels are the tagged member names, as filed.

curl -s "{{BASE}}/v1/companies/320193/segments" -H "X-API-Key: $PROVENANCE_API_KEY"

# or ask your agent (MCP tool company_segments):
# "How did Apple's revenue by region change over the last three years?"

The event feed

GET /v1/events is one ordered feed of new SEC filings, officer changes read from 8-K item 5.02, and listing events. Store next_cursor and pass it back as after; you will never miss or repeat an event.

# catch up from a time, then page with the cursor
curl -s "{{BASE}}/v1/events?since=2026-11-01T00:00:00Z&types=filing&form_type=8-K" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/events?after=NEXT_CURSOR" -H "X-API-Key: $PROVENANCE_API_KEY"

# live, as Server-Sent Events; reconnect with Last-Event-ID
curl -N "{{BASE}}/v1/events/stream?types=filing,leadership" -H "X-API-Key: $PROVENANCE_API_KEY"

Filters: types (filing, leadership, listing), cik, form_type, items (8-K items such as 5.02), mic and event_type. The stream needs your own key; the demo key is not accepted.

Watches and webhooks

A watch sends each new filing of a company, or each listing event in a market, to your webhook or email. Creating a webhook watch returns a webhook_secret once; use it to check that a delivery came from Provenance.

Builder plans and up can watch event types across companies (any restatement, any auditor change) with POST /v1/type-watches, optionally narrowed by SIC prefix, exchange, filer category or a list of CIKs; busy types like results arrive as one batch an hour.

curl -s -X POST "{{BASE}}/v1/watches" -H "X-API-Key: $PROVENANCE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"cik": "320193", "destination_type": "webhook", "destination": "https://example.com/hooks/sec"}'

Each delivery is a JSON POST with X-Event-Type (sec.filing.detected or listing.<event>), X-Event-Id, Idempotency-Key, X-Signature-Timestamp and X-Signature. The signature is HMAC-SHA256 of timestamp.body with your secret, sent as v1=<hex>. Reject a timestamp more than five minutes old, and treat a repeated X-Event-Id as already handled.

import hashlib, hmac, time

def verified(secret: str, timestamp: str, signature: str, body: bytes) -> bool:
    if abs(time.time() - int(timestamp)) > 300:
        return False
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest(signature, "v1=" + mac.hexdigest())
import { createHmac, timingSafeEqual } from "node:crypto";

export function verified(secret, timestamp, signature, rawBody) {
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false;
  const mac = "v1=" + createHmac("sha256", secret).update(`${timestamp}.`).update(rawBody).digest("hex");
  return mac.length === signature.length && timingSafeEqual(Buffer.from(mac), Buffer.from(signature));
}

A failed delivery is retried with growing delays, up to six attempts. GET /v1/watches/{id}/deliveries shows each attempt and its status code. Destinations on private networks are refused.

Listings in Canada, the UK and the EU

New listings, delistings and suspensions on covered venues, from the ESMA and FCA instrument registers, with issuers identified through GLEIF. A new_listing means an instrument first traded on a venue; it is not an IPO determination. issuer_requested: true marks a likely primary listing.

curl -s "{{BASE}}/v1/markets/events?event_type=new_listing&region=uk" -H "X-API-Key: $PROVENANCE_API_KEY"
curl -s "{{BASE}}/v1/markets/instruments?q=Exosens&region=europe" -H "X-API-Key: $PROVENANCE_API_KEY"

The last two weeks of events are public, without a key, at Listings.

AI agents

Agents read llms.txt, a plain-text summary of every endpoint, and openapi.json. Tell your model to cite source_url for every figure it states. The Financial Chat is built this way: each answer links the filings it used.

MCP server

Claude, ChatGPT and agent frameworks that speak the Model Context Protocol can use Provenance as a set of tools: find a company, read its overview, get figures (with as_of), list filings, rank companies, search filing text, follow the event feed, see new listings, follow companies going public, map a company's insiders, 5% holders and subsidiaries with their trades, list its institutional holders from 13F, and break its revenue down by segment. Every result keeps the filing link and accession number, so the agent can cite it. Without a key, the demo key's limits apply.

Google Sheets

Two custom functions put a reported figure, and the filing behind it, into a cell. Paste Code.gs into Extensions > Apps Script, and add your key as the script property PROVENANCE_API_KEY with the API address as PROVENANCE_BASE_URL. The key stays in the script, not the sheet.

The period is optional: latest, latest quarter, FY2024, Q2 FY2026, CY2025 or CY2025Q4. A period nobody filed returns not reported, never 0. Each cell is one request against your plan, cached for six hours.

=PROVENANCE("AAPL", "revenue", "FY2024")
=PROVENANCE("MSFT", "operating_income", "CY2025")
=PROVENANCE("320193", "net_income", "Q2 FY2026")
=PROVENANCE_SOURCE("AAPL", "revenue", "FY2024")

Errors

Every error has the same shape, and the code is stable, so branch on it rather than on the message. Quote request_id when you ask for help.

{"error": {"code": "company_not_found", "message": "No company with CIK 0000000001", "request_id": "req_3f2a9c0d1b7e4a55"}}
StatusCodeWhat to do
401missing_api_key, invalid_api_keySend a valid key in X-API-Key.
403demo_scope, demo_limit, semantic_needs_key, sessions_need_keyThe demo key cannot do this. Use your own key.
404company_not_found, watch_not_found, instrument_not_found, issuer_not_found, filing_not_found, watchlist_not_foundCheck the identifier. A CIK can be given with or without leading zeros.
404changes_not_availableThat report is not compared yet; error.reason says why (not_read, prior_not_read, not_split, not_annual_report). Try the company’s latest 10-K, or later.
202(not an error)The company is being loaded. Retry after the Retry-After seconds.
413export_limit_exceededAsk for fewer rows, or page through the results.
422invalid_parameter, invalid_cursor, invalid_destination, watch_limit_reachedFix the request; the message names the parameter.
429rate_limited, quota_exceeded, stream_limitWait for Retry-After seconds, then retry.
5xxinternal_error, service_unavailableRetry with backoff. The Python client does this for you.
